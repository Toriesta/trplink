# 任务自动分发与结款：架构与边界

写给下一步（上服务器前）的自己。现在已落地的是**保密分级与人工派单**，
LLM 判定与自动结款是目标态，这里把接口、硬规则和现实约束写清楚，避免以后推倒重来。

## 一、保密分级（已实现）

| 级别 | 含义 | 谁能看 | 谁能接 | 存放位置 |
| --- | --- | --- | --- | --- |
| A | 最高机密，必须自己做 | 只有管理员 | 不派、不外发 | 本机 `tasks-private.json`，**永不进仓库** |
| B | 商业敏感，只给可信成员 | `trusted=true` 的人 | 可信成员，或管理员直接指派 | 仓库 `tasks.json` |
| C | 常规外包 | 所有已登录成员 | 任何人 | 仓库 `tasks.json` |

硬规则（任何环节都不得绕过）：

1. A 级不得写入共享仓库、不得 `--assign-to`、不得出现在手机端接口返回里
2. B 级只对人才库 `trusted=true` 的人可见；未授权者连列表都看不到
3. 手机端在读取、接单两处都校验等级，不只靠 UI 隐藏
4. LLM 只能**调高**等级（C→B→A），不能调低；管理员可以人工降级并留痕

管理员命令：

```bash
# 加人 / 授权可信
python tools/publish_task.py --admin SimoHoia0523 --add-worker wx_id --worker-name 名字
python tools/publish_task.py --admin SimoHoia0523 --trust-worker wx_id
python tools/publish_task.py --admin SimoHoia0523 --untrust-worker wx_id

# 发布
python tools/publish_task.py --admin SimoHoia0523 --secret A --title "..."      # 只留本机
python tools/publish_task.py --admin SimoHoia0523 --secret B --title "..." --assign-to wx_id
python tools/publish_task.py --admin SimoHoia0523 --secret C --title "..." --push
```

## 二、LLM 自动分发（目标态）

### 流程

```
任务文本（标题/要求/交付物/金额/截止/客户）
        │
        ▼
[1] LLM 结构化抽取 ──► secret 建议 / 技能标签 / 工时估算 / 风险点
        │                 （规则兜底：关键词命中「腾讯、合同价、素材源」→ 至少 B）
        ▼
[2] 候选池硬过滤 ──► A 级直接终止（不进池）
        │             B 级只留 trusted=true
        ▼
[3] 打分排序（可解释）
        │   技能匹配 40% · 历史交付 25% · 当前负载 20% · 成本 15%
        ▼
[4] 生成建议单 ──► 「这单建议给谁、为什么、风险是什么」
        │
        ▼
[5] 管理员确认（强制闸门）──► 写仓库 / 指派 / 改等级
        │
        ▼
[6] 状态回写 ──► 接单、提交、验收、结款
```

### 数据契约（草案）

LLM 只返回这个结构，服务端再做校验，避免模型直接写库：

```json
{
  "secret": "B",
  "secret_reason": "含客户名称与合同单价，按商业敏感处理",
  "skills": ["剪辑", "字幕"],
  "hours": 12,
  "risk": ["素材授权未确认"],
  "candidates": [
    {"wechat": "chenchengfang", "score": 86,
     "reasons": ["做过同类 4 集", "本周空闲 18h", "历史一次返修"],
     "downgrades": ["未接过腾讯项目"]}
  ]
}
```

服务端校验清单：`secret` 不得低于规则判定值；候选必须存在于人才库且满足等级；
去重；单人负载不超过可用工时；金额超过阈值需二次确认。

### 现在能做的过渡版

不接模型也能跑：用关键词 + 历史数据做规则打分，输出「建议指派」清单，
管理员确认后写库。等有服务器再接模型，接口不变（`suggest()` 出入参一致）。

## 三、结款：能自动到哪一步

先说实话：**个人微信号 / 个人支付宝无法合法调用转账 API**。
自动打款的前置条件是商户资质，绕不开。可行路径对比：

| 方式 | 需要什么 | 自动化 | 现实评价 |
| --- | --- | --- | --- |
| 微信支付「商家转账到零钱」 | 企业营业执照 + 商户号 + 实名 | 全自动 | 个人号不行；小额高频要报备场景 |
| 支付宝「转账到支付宝账户」 | 企业账户 + 开放平台签约 | 全自动 | 同上，需签约与风控审核 |
| 银行代发（对公） | 对公账户 + 代发协议 | 批量自动 | 适合月结，不适合单笔秒结 |
| 第三方代付（连连、PingPong、空中云汇） | 企业主体 | 半自动 | 跨境好用，境内个人结算受限 |
| 平台托管（Upwork / 猪八戒） | 无 | 平台代付 | 抽成 5–20%，但省心、有凭证 |
| **人工转账 + 系统记账** | 无 | 半自动 | **现阶段推荐**，系统负责清单、凭证、对账 |

不建议做的事：用个人收款码轮询、破解/模拟支付客户端、找「代付接口」灰产。
违反支付服务协议，出事没有凭证，也过不了任何审计。

### 建议的落地方案（下一轮实现）

任务表加结款字段，把「转账」这一步留在人手上，其余全自动：

```json
{
  "payout": {
    "status": "pending",        // pending | paid | held
    "amount": 1200,
    "payee": "chenchengfang",
    "method": "微信转账",
    "paidAt": "",
    "voucher": "https://…",     // 转账截图/回单链接
    "note": ""
  }
}
```

- 任务验收通过 → 自动生成结款单（金额、收款人、账期）
- 管理员转账后运行 `--pay T-2611-01 --voucher 链接` 标记已付
- 手机端「我的」显示「待结 / 已结」，可查看凭证
- 月底自动汇总一份对账单（金额、笔数、未结），可直接给会计

这一套不依赖任何支付资质，等有了商户号，把「人工转账」换成「调用转账 API」
即可，数据结构和界面都不用改。
